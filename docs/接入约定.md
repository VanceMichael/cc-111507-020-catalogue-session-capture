# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 filter、version、region、tables、view、query、client、basisPath。raw 已上线，只领取入口文件并记录元信息。structured 通过来源网关会话完成联合检索：`query` 为检索式，`preferredSyntax` 为偏好呈现格式（默认 mods，也支持 marcxml），`resultSetName` 可指定结果集名（缺省为本次采集的唯一名称），`pageSize` 为每批领取数量（1 到 100，默认 2）。每次采集单独开会话、检索一次，再按 `nextResultSetPosition` 逐批领取直至覆盖 `resultCount`，不把首屏数量当作全部结果。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件结果。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，语法错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

结构化记录可增加领域字段，但来源定位必须可追溯，稳定身份不得仅使用数组下标。接收后查询返回相同记录；新的实例打开相同 DATA_DIR 仍可查询既有结果。请求只有本机合成来源，不接受任意互联网地址。

领域输出约定：records 只保存可呈现书目；逐记录拒绝写 issues，存在拒绝则本次 state=partial。

结构化结果的字段约定：

- records 每条含 `identity`（取正文标识：MODS 的 `identifier`，MARCXML 的 001，缺 001 时依次退到 010/020）、`title`、可选 `creators/publisher/date/language/extent/form/edition/identifiers`、`syntax`（mods 或 marcxml）、`position`、`resultSet`（session/name/generation）和 `evidence`（记录正文的 SHA-256 摘要）。序号只在所属会话、结果集名和代次中有效，不能当作稳定身份。
- issues 分两类。`scope: "record"` 为逐记录问题：`kind: "source-diagnostic"` 表示来源用 surrogateDiagnostic 明确拒绝呈现该条目（保留 condition 和原文），`kind: "presentation"` 表示该条目正文无法按声明的受支持格式解析（如缺正文标识、XML 不良、格式不受支持）；这类问题不是书目，不能放进 records。`scope: "result-set"` 表示整段结果集不可用或无法确认完整，`kind: "result-set-invalid"` 记录 source 返回的 session-expired/set-replaced 等操作诊断，`kind: "incomplete"` 记录提前结束、序号错位、位置不前进等未领取完的情况。
- coverage 说明 `resultCount`、`recordsReturned`、`recordsCollected`、`recordDiagnostics`、`pagesFetched` 和结果集上下文；`complete` 仅在全部批次领取完且每条结果要么成为记录要么有逐记录问题时为 true。整段结果集失效时收件为 state=rejected、records 为空、coverage.state=result-set-invalid，此前领到的批次一并作废（`discardedRecords` 记录数量）。
- evidence 保存本次检索的 `resultSet` 与逐批 `pages` 轨迹；正文在 blobs 中按摘要留存。未列出的格式扩展保留原文并写入逐记录问题，不假装完整解析。
